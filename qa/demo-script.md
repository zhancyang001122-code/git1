# 三分钟 Production Live 演示脚本

## 会前预检（不占现场时间）

在 `web/` 执行：

```powershell
pnpm interview:preflight
```

该命令要求工作区干净、Git SHA 与 Production 完全一致，并验证 Live 健康状态、非法请求边界、真实高德地理编码、作品集首方 RAG、租房主线三工具链路及主要浏览器流程。它会写入测试对话和反馈，不用于高频监控，也不会读取或打印密钥。

## 0:00–0:25：先讲问题，不先讲技术

优先打开[正式域名](https://xiaozhi.zaneyang.xyz)；如果本机代理对自定义域名超时，立即使用已验收的 [Vercel 备用入口](https://xiaozhi-local-life.vercel.app)。两者指向同一 Production 部署。进入首页后指向“从预算到签约核验，一次问完”。

> 租房者往往要在房源平台、地图和政策页面之间来回切换。纯聊天回答又容易把历史房源、推测距离或模型记忆当成事实。我把项目收敛成一个租房决策任务，让三类数据各自从正确系统取得。

点击“查看交付证据”，快速展示已验证数据和“尚未完成真实用户效率验证”的边界。

## 0:25–1:45：运行唯一主演示

点击“立即运行主演示”，发送预置问题：

> 我预算 3500 元，想找武林广场附近的一居室。请查询 2024 年历史房源，再找附近的地铁和超市，并说明签约前需要核验哪些信息、是否需要办理网签备案。

依次观察并讲解：

1. 处理进度显示房源、高德和知识检索，不展示模型思维链。
2. 房源卡来自 Supabase 的 2024-11 历史数据，不能说“目前可租”。
3. 周边卡标记“高德地图”；高德失败时不能让模型猜距离。
4. “回答依据”标记“官方公开资料”，显示版本、生效日期，并可打开官方原文。
5. 调试摘要只显示工具名、参数摘要、耗时、结果数和错误码，不泄露 Prompt、密钥或隐私。

30 秒回答：

> 精确价格和户型查结构化数据库，地点与路线查高德，签约规则查已发布、有效并带来源的知识版本。千问负责理解问题、调用白名单工具和组织答案，但不负责创造房态、距离或政策事实。任一工具失败时，系统只保留其余可信结果并说明缺口。

## 1:45–2:25：证明 RAG 不是装饰

展开一张官方引用并说明：

- 官方资料使用独立 `public_official` 来源类型，不与模拟知识混在一起；
- 引用事件保留标题、版本、生效日期、`chunkId` 和官方原文 URL；
- 知识经过候选、审核、发布、索引和评测后才进入检索；
- 官方租赁资料集的 10 条独立必答/拒答用例 10/10 通过；原有作品集首方集为 20/20，千问生成用例 4/4。

> RAG 不是把资料重新训练进模型，而是回答前检索当前有效版本。价格和房态不适合用相似检索，所以仍由业务工具负责。

## 2:25–2:50：展示工程交付证据

```text
UI
  -> Next.js API / application services
      -> strict Tool Registry + Zod
          -> Supabase / AMap / Knowledge / User Memory adapters
      -> Qwen Provider
```

说明三点：运行时 Zod 校验、外部调用超时/稳定错误、Supabase RLS 与服务端密钥边界。测试数量会变化，现场只引用刚执行成功的质量命令和任务报告，不背过期数字。

如面试官要求查看偏好写入，可使用公开固定演示码 `666666` 进入共享演示账号。它仍使用真实 Supabase Session 与 RLS，但不属于主演示，也不能冒充面向公众的生产级身份认证。

## 2:50–3:00：诚实结束

> 这个作品证明我能把模糊需求收敛为可部署、可观测、可评测的 AI 业务薄切片。房源是历史数据，团购与超市交易是演示业务，官方摘要不构成法律意见；真实用户 ROI 还没有样本，所以我准备了 3–5 人的验证方案，而不会编造收益。

## 网络故障时

1. 展示案例页、架构和最近一份通过的任务报告，不在面试现场修改密钥。
2. 说明最近一次预检验证了哪些链路，不把历史成功说成当前请求成功。
3. 如切换 Demo，必须明确它是确定性模拟数据，不能冒充 Supabase、高德或千问 Live 结果。
