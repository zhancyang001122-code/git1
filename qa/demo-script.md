# 三分钟 Production Live 演示脚本

## 演示前检查（约 20 秒）

1. 打开 [Production Live](https://xiaozhi-local-life.vercel.app)，使用手机或 390–430px 浏览器视口。
2. 确认 `/api/health` 返回 `mode: "live"`，Supabase、Qwen、AMap 和 housing 均为 `configured`。
3. 新建空白对话。不要在现场临时修改环境变量或数据库。

如需会前自动冒烟，在 `web/` 执行：

```powershell
$env:EXPECTED_PRODUCTION_MODE='live'
pnpm deploy:verify-production
```

该命令会创建两条测试对话和一条点赞反馈，不用于高频监控。

## 场景一：历史房源 + 高德（约 60 秒）

输入：

> 请帮我查杭州武林广场附近、3500元以下的一居室，并同时用高德查附近超市。房源和周边都要分别查询。

讲解与观察点：

1. UI 先显示“正在查询房源”和“正在查询周边地点”，不展示模型思维链。
2. 房源卡来自 Supabase 的 2024-11 历史数据，必须显示“2024 历史房源数据”，不能说“目前可租”。
3. 周边卡来自高德 Web Service，必须显示“高德地图”，不能出现“接口演示数据”。
4. 房源的历史坐标直线距离与高德路线是两类事实，不能混称。
5. 点“回答有帮助”，页面应显示“感谢反馈，已记录。”，对应反馈写入 Supabase。

一句话讲解：结构化筛选查业务数据库，地点与路线查地图，大模型只负责理解、编排和表达。

## 场景二：商品 + 授权偏好（约 50 秒）

输入：

> 帮我找30元以内有库存的早餐，并记住我不吃辣。商品和偏好都要分别处理。

讲解与观察点：

1. 商品查询返回不超过 30 元且有库存的结构化卡片，并显示“演示业务数据”。
2. 库存来自 Supabase 结构化查询，不由模型从描述文本推断。
3. “不吃辣”只生成“待你确认的长期偏好”卡，尚未写入数据库。
4. 点击“取消”后显示“已取消，本次没有保存长期偏好”，证明模型不能替用户授权。
5. Production 云端保存需要作者白名单邮箱登录；当前游客演示只展示零副作用提案边界。

一句话讲解：模型可以建议写什么，但真正写入个人数据必须由用户界面动作和登录会话共同授权。

## 架构与工程证据（约 35 秒）

展示 README 架构图或代码目录，并说明：

```text
UI
  -> Next.js API / application services
      -> strict Tool Registry + Zod
          -> Supabase / AMap / Knowledge / User Memory adapters
      -> Qwen Provider
```

- 相同工具和参数单轮去重；无效参数只允许修复一次；最多 8 轮。
- 外部调用有超时、错误归一化、局部降级和脱敏工具审计。
- 当前质量证据：438 个 Vitest、103 个 pgTAP、17 条 SQL Role RLS、14 条 PostgREST 权限检查、47 个默认 E2E 通过，2 个专项环境用例按配置跳过；Production Live 双场景连续通过。
- 四个 Demo 知识版本已通过持久化队列、独立 Worker、百炼 Embedding 和 Supabase pgvector 完成 Production 检索；管理视图还会显示逐请求分档的模型公开原价估算及覆盖率。

## 诚实边界与结束陈述（约 15 秒）

> 小智不是单纯聊天页面：它把真实历史房源、真实地图服务、模拟交易业务和受控用户操作放在同一套 Agent 架构中，并明确区分来源。千问、高德、Supabase、Embedding Worker 和 Demo 知识检索已在线接通；但我还没有正式客服资料，所以预置政策只标为演示资料，不把“技术链路已通”包装成“正式 RAG 内容已验收”。

> 这张未使用的演示团购券能退款吗？如果已经过期两天呢？
