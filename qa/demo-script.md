# 三分钟主演示脚本

## 演示前检查（约 30 秒）

- 当前可使用本地 production build；获得 Vercel URL 后再切换为线上页面。使用手机或 390px 浏览器视口。
- `/api/health` 中 Supabase、Qwen、AMap 状态正确。
- `NEXT_PUBLIC_DEMO_MODE` 与页面标签一致。
- 房源、知识和评测种子数据存在。
- 新建空白对话，打开“查看处理过程”。

## 场景一：结构化业务查询（约 35 秒）

输入：

> 帮我找 3500 元以内、允许养猫的一居室。

期望：

1. 显示“正在查询房源”。
2. 调用 `search_houses`，不调用 `search_knowledge`。
3. 返回武林晴川一居室和中山北路温馨一居等满足全部条件的演示卡片。
4. 卡片价格、宠物字段与房源列表完全一致。
5. 讲解：结构化条件必须查业务数据库，不能用 RAG 模糊匹配。

## 场景二：RAG 规则回答（约 35 秒）

输入：

> 未使用的团购券可以退款吗？

期望：

1. 调用 `search_knowledge`。
2. 回答“未使用、未核销、有效期内、不可退套餐除外”等演示条件。
3. 展示《团购券退款规则》、v1.0、生效日期和引用摘录。
4. 不把具体团购卡片的退款标签当完整平台政策。
5. 讲解：原始文章、版本和向量切片分离；答案可追溯。

## 场景三：多工具组合（约 55 秒）

输入：

> 帮我找武林广场附近 3500 元以内、允许养猫的一居室，附近最好有超市，再告诉我宠物规则。

期望执行顺序：

1. `search_houses`
2. 调用 `search_nearby_places`；只有明确询问路线时才调用 `calculate_walking_route`
3. `search_knowledge` 查询宠物规则
4. 分别展示房源卡、周边卡和知识引用；当前 Demo 不宣称完成真实距离综合排序

UI 显示公开进度，debug 面板显示工具、来源、耗时。若高德失败，应保留房源结果并说明暂时无法核验周边，不得编造超市和步行时间。

## 场景四：知识进化闭环（约 45 秒）

第一次输入（使用当前确定性测试问法）：

> 团购券过期两天可以退款吗？

期望：知识库没有统一过期时限，小智拒绝确定性结论，建议人工核验，并生成 `knowledge_candidate`。

打开知识运营页：展示候选来源、脱敏问题、缺口原因、已有证据。演示审核与发布一个新版本，再运行索引和相关 eval。第二次换一种问法，展示新版本引用。

## 结束陈述（约 15 秒）

> 小智不是单纯聊天页面。它把结构化业务查询、地图实时服务、可追溯 RAG 和知识运营闭环统一在一个 Agent 中；Demo 数据和真实外部数据被明确区分，关键业务事实不由模型自由生成。
