# 三分钟 Production Live 演示脚本

## 演示前检查（约 20 秒）

1. 打开 [Production Live](https://xiaozhi.zaneyang.xyz)，使用手机或 390–430px 浏览器视口。
2. 打开 `/api/health`，确认 `mode: "live"`，Supabase、Qwen、AMap 和 housing 均为 `configured`。
3. 返回首页并新建空白对话。现场不要修改环境变量、数据库或供应商控制台。

会前在 `web/` 执行一次实时总检查：

```powershell
pnpm interview:preflight
```

该命令检查当前 Git/部署 SHA、四项 Live 服务状态、真实高德地理编码、非法请求边界、首方 RAG，以及房源 + 高德、商品 + 偏好、反馈的完整浏览器链路。它不读取或打印密钥，会新增三条测试对话和一条反馈记录，因此不用于高频监控。

## 场景一：历史房源 + 高德（约 55 秒）

输入：

> 请帮我查杭州武林广场附近、3500元以下的一居室，并同时用高德查附近超市。房源和周边都要分别查询。

观察并讲解：

1. 页面显示“正在查询房源”和“正在查询周边地点”，不展示模型思维链。
2. 房源卡来自 Supabase 的 2024-11 历史数据，显示“2024 历史房源数据”，不能说“目前可租”。
3. 周边卡显示“高德地图”，不能出现“接口演示数据”。
4. 历史房源坐标的直线距离与高德路线属于不同事实，不能混称。
5. 点“回答有帮助”，页面显示“感谢反馈，已记录。”，反馈写入 Supabase。

30 秒回答：

> 结构化筛选查业务数据库，地点和路线查高德。千问负责理解问题、选择白名单工具和组织语言，不负责产生房租、可租状态或距离事实。

## 场景二：作品集首方 RAG（约 45 秒）

输入：

> 千问在小智里负责什么，它本身是事实来源吗？

观察并讲解：

1. 回答先调用 Knowledge Service，不由模型凭记忆直接说明项目架构。
2. 回答应说明千问负责理解、工具编排和表达，但不是价格、库存、状态、政策或距离的事实来源。
3. 引用卡显示“作品集首方说明”、标题、版本和生效日期；底层引用事件同时保留 `chunkId` 供追踪。
4. 该结果来自四份项目首方公开资料，不是企业客户客服资料，也不是模拟退款政策。

30 秒回答：

> RAG 不是把资料训练进模型，而是回答前检索已发布的有效版本。当前固定集 20/20 通过，其中 4/4 是千问自然问法生成测试；这能证明项目首方知识链路，不能冒充企业客户知识库交付。

## 场景三：商品 + 授权偏好（约 45 秒）

输入：

> 帮我找30元以内有库存的早餐，并记住我不吃辣。商品和偏好都要分别处理。

观察并讲解：

1. 商品卡不超过 30 元且有库存，并显示“演示业务数据”。
2. 库存来自 Supabase 结构化查询，不从商品描述或 RAG 推断。
3. “不吃辣”只生成待确认的长期偏好，模型不能自行保存个人数据。
4. 点击“取消”时不写入；如要演示保存，进入登录页，使用公开固定演示码 `666666` 登录共享演示账号，再由用户点击确认。
5. 固定演示码已通过真实 Supabase Session 与 RLS 验收，但共享演示账号不是生产级公众认证。

30 秒回答：

> 模型可以提出偏好写入建议，但真正写入必须同时满足登录会话、用户界面确认和数据库 RLS。固定码是作品集低频演示取舍，不适合真实用户系统。

## 架构与工程证据（约 30 秒）

```text
UI
  -> Next.js API / application services
      -> strict Tool Registry + Zod
          -> Supabase / AMap / Knowledge / User Memory adapters
      -> Qwen Provider
```

- 工具参数在运行时校验；同轮相同工具和参数去重；模型最多执行有限轮工具循环。
- 外部调用有超时、有限重试、稳定错误码、局部降级和脱敏审计。
- 当前代码质量门：129 个 Vitest 文件、548 项测试、43 个生产路由；完整本地 Supabase 数据库套件连续两遍 204/204 通过。
- 浏览器 E2E：48 项通过；1 项依赖独立本机房源服务，未启动服务时按配置跳过。固定演示码 Auth 专项 1/1 通过。
- Production 固定 RAG：20/20 通过，其中千问自然问法生成 4/4；Live 房源、高德、演示商业、偏好提案和反馈回归通过。

## 诚实边界与结束陈述（约 15 秒）

> 小智不是单纯聊天页面，也不是已提交微信审核的原生小程序。它是 430px 移动 Web，把真实历史房源、真实高德、真实 Supabase、千问工具编排、作品集首方 RAG 和模拟交易业务放在统一架构里，并在界面上区分来源。企业客服材料、qwen3-rerank 在线调用和外部值班通知仍未完成，我不会用首方资料或 Adapter 测试冒充这些交付。

## 网络故障时怎么处理

1. 先展示本地备份材料和架构图，不在现场排查密钥或供应商控制台。
2. 说明 Production 上一次回归覆盖了什么，并展示 `docs/task-reports/` 中的证据，而不是声称当前网络请求成功。
3. 如切到 Demo 模式，必须明确说是确定性演示数据；不能把 Demo 卡片说成刚从高德、Supabase 或千问取得。
