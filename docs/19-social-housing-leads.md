# 社交平台租房线索管道

## 1. 产品定位

这套数据不是“实时可租房源”，而是帮助用户发现公开租房帖子的线索库。帖子发布者身份、当前房态、租金、地址和合同均由用户打开原帖后自行核验。界面统一显示 `社交平台租房线索` 与 `房态未经核验`。

它与 `historical_houses` 分表管理：后者是 2024-11 历史结构化数据，前者是有来源链接和审核生命周期的近期公开帖子，不能混写或互相冒充。

## 2. 数据流

```text
MediaCrawler 本机低频搜索
  -> 原始 JSONL（仓库外，仅本机）
  -> 联系方式脱敏
  -> qwen3.7-plus 结构化分类/字段抽取
  -> 硬规则：出租而非求租、非攻略/商业获客、未明确结束、有租金、有可定位地点
  -> 高德地理编码 GCJ-02 + 转 WGS84
  -> 区县级粗坐标拦截，区域冲突转人工复核警告
  -> 人工展示审核
  -> Supabase 独立表 + RLS + 服务端 RPC
  -> `/api/housing-leads`
  -> `/houses` 近期线索页签与 `/houses/[id]` 来源详情
```

模型不决定最终上线。它只输出受 Zod 约束的候选字段；代码负责枚举、数值、日期、坐标和 URL 校验，人工负责判断模板化获客等难以完全规则化的问题。

模型置信度不是准入硬门槛，只作为人工复核参考。低置信但字段完整的帖子仍会进入人工复核，避免把社交平台线索误当成高可信库存后过度筛除。

## 3. 采集与隐私边界

- MediaCrawler 固定在提交 `d6f7c5bb906b6dac40ddf343ef9e26438a3de092`，使用独立 Chrome profile、单并发、不抓评论和媒体文件。
- 原始 JSONL 位于 `C:\Users\Administrator\Tools\MediaCrawler\data\`，不提交 Git、不上传 Vercel 或 Supabase。
- 在发送给千问前先隐藏手机号、微信号等联系方式；不传昵称和作者主页。
- Supabase 不保存昵称、联系方式、原始正文、评论、图片、`xsec_token` 或 Cookie，只保存原始载荷 SHA-256 用于幂等审计。
- canonical 链接只允许小红书 24 位帖子 ID 或抖音数字视频 ID，查询参数一律剥离。

## 4. 准入规则

允许展示：普通发布者提供具体房源出租/转租；帖子在 120 天发现窗口内；租金可为单值或区间；地点可定位到小区、明确地标或地铁站；原文没有明确“已租出/已结束”或已过有效期。

拒绝展示：求租、租房攻略/讨论、明显中介或模板化获客、明确已结束、无租金、无可定位地点、只能定位到整个区县。

帖子文字中的区与高德地理编码跨区时不自动删除，而是记录人工复核警告，并以高德返回的区作为距离展示字段。原因是同名小区、地铁站和模型抽取都可能造成跨区差异，这种冲突不足以证明帖子无效。

`approved` 只表示“通过本项目展示审核”，不表示房态真实。来源状态 `not_obviously_closed` 只表示原帖没有明确写已结束。

## 5. 本机操作

处理脚本默认只生成仓库外审核文件：

```powershell
cd C:\Users\Administrator\Desktop\git1\web
pnpm housing:social-pilot -- --as-of 2026-09-03T02:30:00.000Z
pnpm housing:social-import
```

`housing:social-import` 默认是 dry-run。只有完成 `manual-decisions.json` 后才使用 `--apply`。脚本按批次 checksum、线索 dedupe key 和平台帖子 ID 幂等写入；中途失败将批次标记为 `failed`，可以修复后重跑。

## 6. 首批验证记录

2026-09-03 首批搜索得到 40 条、去重后仍为 40 条，其中 26 条进入 120 天分类窗口。取消模型置信度硬门槛、把跨区解析改为 POI 重查后，有 7 条进入人工复核：4 条批准；2 条因不同账号的内容结构和措辞高度重复、疑似模板化获客而拒绝；1 条因只写“地铁 1 号线附近”而没有具体站点、小区或地标被拒绝。

本地与远端 Supabase 验证结果：4 条能按武林广场 WGS84 坐标计算距离；`2000 元以内`返回 3 条；列表与详情响应不包含临时 token。高德并发错误 `10021` 采用退避重试，单条失败会转为拒绝原因而不是中断整批。小区和地标优先使用高德 POI 文本搜索，行政区用于结果消歧，找不到 POI 时才回退到地理编码。

## 7. 当前限制与后续

- 小红书需要人工扫码维持本机登录；这不是无人值守生产采集系统。
- 原帖可能删除或变更，面试前应重新采集并复核；当前没有自动证明房态的机制。
- 当前只接入小红书首批数据；抖音仍只有数据模型和 URL 契约，没有已验证采集样本。
- 当前没有把近期线索注册为小智 Agent 工具，避免模型在没有引用工具的情况下假装读取帖子。
