## 1. 一句话定义

小智是一个以自然语言为入口的租房决策 AI 助手。它把历史房源筛选、高德周边核验和官方租赁知识连接成一次完整任务，帮助用户完成“按预算找参考房源—核验生活配套—理解签约与备案依据—明确下一步核验”的决策过程。

它不是一个把大模型接到聊天框里的演示，也不声称提供实时可租房源或法律意见。它用一个可验收的业务薄切片展示企业 AI 应用完整链路：需求澄清、结构化查询、外部 API、工具编排、RAG、权限控制、可观测性、异常降级和知识迭代。团购、超市和社区继续保留为扩展框架，但不再承担面试主演示。

## 2. 背景与问题

用户在本地生活场景中的问题往往包含多个条件，例如：

> 我预算 3500 元，想找武林广场附近的一居室，附近最好有地铁和超市。

传统产品通常要求用户在多个页面反复筛选，而且房源、地图、商品、规则说明分别属于不同系统。普通聊天机器人虽然可以生成一段看似完整的回答，却容易出现以下问题：

- 把历史房源误说成当前可租房源。
- 把模型猜测当成价格、库存、距离或退款政策。
- 无法解释用了哪些数据和工具。
- 外部服务超时后仍然编造结果。
- 客服规则变更后，旧内容仍然参与回答。
- 用户纠错没有进入可审核的知识改进流程。

小智的核心价值是：让不同来源的数据各司其职，并且让用户看得懂结果从哪里来、哪些信息可信、哪些仍需确认。

## 3. 产品目标

### 3.1 用户目标

1. 用一句自然语言提出找房、团购、买菜、周边搜索或规则咨询需求。
2. 获得满足明确筛选条件的结构化结果，而不是只有一段生成文本。
3. 看见房源数据年份、地图来源、模拟业务标识和知识引用。
4. 在复杂任务中看见“正在查询房源”“正在搜索周边”等公开进度。
5. 外部服务无结果、超时、低置信或知识冲突时得到诚实说明。
6. 明确授权后保存长期偏好，并允许当前对话条件覆盖历史偏好。

### 3.2 作品集与面试目标

1. 在 3 分钟内演示结构化查询、外部 API 和 RAG 三类能力。
2. 能解释为什么业务数据不能全部放进向量数据库。
3. 能解释 Zod 校验、稳定工具返回、超时、错误归一化和降级策略。
4. 能展示 Supabase RLS、服务端密钥边界和最小权限原则。
5. 能展示知识从候选、审核、发布、索引到评测的闭环。
6. 能用测试、日志和验收证据证明功能，而不是只展示页面截图。

### 3.3 V1.0 成功标准

- 三条核心演示链路在演示环境中连续执行成功。
- 所有真实、历史、模拟和 AI 生成内容均有清晰来源标识。
- 价格、库存、状态、距离和政策不由模型自行编造。
- 低置信、知识冲突和外部服务失败均有可理解的降级结果。
- 五个主页面和关键二级页面可完整浏览和交互。
- 项目可以在无真实密钥的 Demo 模式运行，也可以通过环境变量切换真实服务。

### 3.4 面试主演示成功标准

- 一个问题必须实际执行 `search_houses`、`search_nearby_places` 和 `search_knowledge`，不能只在回答中口头描述三种能力。
- 房源结果必须标记 `2024-11` 历史数据；高德结果必须标记外部来源；租赁规则必须引用官方公开资料并可打开原文。
- 任一工具失败时保留其余可信结果，并明确缺失项；不得用千问补造房态、距离或政策。
- 仓库测试、生产预检和案例页只展示已验证证据。真实用户效率尚未测量前，不宣称节省时间、提升转化或替代专业法律判断。

## 4. 目标用户与核心场景

### 4.1 普通用户

- 初到杭州或绍兴，需要根据预算、户型和通勤地点筛选历史房源参考。
- 想了解附近的餐饮、超市、地铁、医院等真实 POI 和步行路线。
- 想查询演示团购、商品和库存，体验 AI 辅助决策。
- 对退款、押金、配送和平台规则有疑问，希望看到引用依据。

### 4.2 运营与知识审核人员

- 查看用户点踩、纠错、无结果和低置信形成的知识候选。
- 审核新版本内容，设置生效日期并发布。
- 触发幂等索引，确认检索版本与已发布版本一致。
- 查看检索和回答评测结果，定位知识缺口。

### 4.3 面试官或业务决策人

- 快速理解产品解决的真实问题和演示边界。
- 检查 AI 是否真正调用业务系统，而不是依赖 Prompt 表演。
- 检查异常处理、安全、可观测性和后续扩展能力。

## 5. 数据真实性与演示边界

这是本产品最重要的产品约束。界面和回答必须区分“真实当前数据”“真实历史数据”“模拟数据”和“生成内容”。

| 数据或能力                   | V1.0 来源                              | 真实性定义                             | 前端必须展示                       |
| ---------------------------- | -------------------------------------- | -------------------------------------- | ---------------------------------- |
| 房源                         | 清洗并导入 Supabase 的 2024 年房源数据 | 真实历史记录，不代表当前仍在租或仍可租 | `2024 历史房源`                    |
| 社交平台租房线索             | 公开帖子经脱敏、结构化和人工展示审核   | 帖子线索，不核验发布者身份或当前房态   | `社交平台租房线索`、`房态未经核验` |
| 周边 POI、地理编码、步行路线 | 高德 Web Service API                   | 接口成功时为实时外部查询结果           | `高德地图`                         |
| 团购、商家、商品、库存、订单 | Supabase 演示数据                      | 模拟业务，不对应真实交易               | `演示数据` / `演示订单`            |
| 社区帖子                     | Supabase 演示数据                      | 模拟内容                               | `演示内容`                         |
| 收藏、偏好、反馈、对话       | Supabase 用户数据                      | 用户在本产品中的真实交互记录           | 隐私说明和保存状态                 |
| 官方租赁知识                 | 官方公开原文的版本化摘要               | 仅已发布且在有效期内的版本可作为依据   | 标题、版本、生效日期、原文链接     |
| 模拟客服规则                 | 自建版本化知识库                       | 仅用于演示知识治理流程                 | `模拟知识资料`                     |
| AI 文本                      | 千问生成                               | 负责理解、编排和表达，不是事实来源     | 在关键结果旁展示实际数据来源       |

### 5.1 不允许出现的误导

- 不得把 2024 年房源描述为“目前可租”或“实时房源”。
- 不得把社交平台帖子描述为已核验房源；必须保留去追踪参数后的原帖链接，并允许租金区间。
- 不得把演示团购、库存、订单描述为真实商家交易。
- 不得在高德 API 失败后使用模型猜测距离或路线。
- 不得把未发布、已过期或冲突的知识当成确定政策。
- 不得把模型生成内容单独作为价格、库存、政策、生效日期或距离证据。

## 8. 核心用户流程

### 8.1 历史房源组合查询

1. 用户输入预算、户型或附近地点。
2. 小智将参数转换为严格的房源工具输入。
3. 服务端校验参数并查询 Supabase。
4. 如包含“附近地铁/超市”，再调用高德搜索和路线工具。
5. 返回满足条件的房源卡片，明确标记 `2024 历史房源`。
6. 如果没有匹配结果，说明哪些条件导致结果为空，并建议用户放宽条件。

验收示例：输入“武林广场附近 3500 元以下的一居室”，返回结果必须同时满足城市、价格、户型和距离条件；不得把历史记录解释为当前可租，距离也不得冒充步行路线。

### 8.2 周边服务与步行路线

1. 用户提供地点名称或房源坐标。
2. 系统进行地理编码或直接使用可信坐标。
3. 调用高德周边搜索获得 POI。
4. 用户选择目的地后调用步行路线。
5. 返回 POI、距离和预计步行时间，标记 `高德地图`。
6. 超时或无结果时，不返回猜测距离，并提供重试或更换关键词。

### 8.3 规则知识问答

1. 用户询问退款、押金、配送等规则。
2. 系统对问题改写并提取白名单 Metadata。
3. Embedding 后执行向量与文本混合召回。
4. 可选 Reranker 对候选内容重排。
5. 应用层再次校验发布状态和有效期。
6. 高置信且无冲突时回答，并展示完整引用。
7. 低置信、无结果或知识冲突时拒绝确定性结论，引导纠错或人工确认。

### 8.4 知识迭代闭环

1. 点踩、纠错、无结果、低置信或重复追问生成知识候选。
2. 运营人员查看证据和规范化问题。
3. 新建或修改草稿版本，并提交审核。
4. 审核通过后发布新版本，旧版本归档。
5. 对已发布版本执行幂等分块和向量索引。
6. 运行固定评测集；不达标时回滚或继续修订。
7. 只有已发布、已生效、索引成功的版本参与回答。

## 9. 功能需求与验收标准

### FR-01 首页与跨页面入口

- 首页展示定位、搜索框、四个业务入口和精选卡片。
- 首页“更多演示内容”中的每张卡片必须整体可点击，并进入与卡片实体一致的详情页。
- 搜索提交后进入小智并自动携带原问题。
- 五个主页面复用同一个底部导航组件。
- 360–430px 宽度无水平滚动，桌面端以 430px 画布居中。

### FR-02 房源

- 支持城市、租金区间、租赁类型/卧室数、排序和分页。
- 房源列表与详情必须使用同一数据源。
- 房源列表和小智回答中的每张房源卡必须可进入同一条记录的详情页；详情页提供基于真实坐标生成的高德步行导航入口。
- 历史记录展示 `2024 历史房源`；帖子线索展示 `社交平台租房线索` 和 `房态未经核验`，两类来源不得混在同一结果集中。
- 帖子线索只排除求租、攻略/讨论、商业获客、明确已结束、没有租金或没有可定位地标的内容；租金区间按上下限原样保存，不伪造单一价格。
- 帖子线索详情必须展示每个来源平台和 canonical 原帖链接；不得保存昵称、联系方式、临时访问 token 或原帖图片。
- 数据缺字段时显示“暂无记录”，不得由模型补齐。

### FR-03 团购与超市

- 支持团购分类、价格、可退标签和详情。
- 支持商品搜索、分类、价格、库存和购物车。
- 库存只来自结构化库存查询。
- 下单结果统一标记为演示，不发起真实支付或履约。

### FR-04 高德地图

- 支持地点地理编码、周边 POI 和步行路线。
- 小智和周边页返回的 POI 卡片必须提供高德导航入口；导航参数只能来自高德结果或房源记录中的坐标。
- 密钥只能在服务端使用。
- 外部响应必须经过 Zod 校验。
- 超时、限流、无结果和无效响应映射为稳定错误码。
- 路线失败不能影响已经成功返回的业务查询结果。

### FR-05 小智 Agent

- 通过服务端流式 API 输出文本。
- 工具参数严格校验；首次参数错误允许模型修复一次。
- 单轮相同工具和相同参数只执行一次。
- 同一工具因相同业务错误重复失败两次后，本轮停止继续调用并返回稳定错误，避免模型更换参数后无效循环。
- 工具调用最多 8 轮，达到上限后明确结束。
- 结构化卡片与文本使用不同 SSE 事件。
- 用户只看到公开处理步骤，不展示 SQL、完整 Prompt 或内部思维过程。

### FR-06 RAG 知识服务

- 原始文章、版本、分块和向量分离存储。
- 仅 `published` 且当前有效版本可被召回。
- 分块、Embedding 和索引必须可安全重试。
- 引用必须包含文章、版本、分块、标题、版本号和生效日期。
- 低置信或冲突时禁止输出确定性政策结论。
- 索引接口只能索引已发布版本，不能顺便发布内容。

### FR-07 偏好和隐私

- 仅在用户明确要求或确认后保存长期偏好。
- 当前消息中的条件优先于长期偏好。
- 公共知识、个人偏好和对话上下文分别存储。
- 浏览器不能接触 service role、高德或千问密钥。
- 日志不得包含完整隐私内容、密钥或完整 Prompt。

### FR-08 可观测性与调试

- 每次工具调用记录工具名、状态、参数摘要、耗时、来源、结果数和错误码。
- 生产日志只记录排障所需的最小信息。
- 调试面板只能在显式配置后显示。
- 工具审计保存失败不得抹掉已经成功返回的查询结果，但必须给出警告。

### FR-09 Demo 与 Live 模式

- 无外部密钥时，项目可在 Demo 模式完整浏览和演示。
- Demo 模式必须显式标识，不得暗中假装已连接真实服务。
- Live 模式缺少必要配置时启动或调用失败，并返回具体配置错误。
- Demo 模式不得写入或发布真实知识索引。

## 10. AI 与数据架构原则

```text
UI
  → Application Services
      → Business / Maps / Knowledge / User Ports
          → Supabase / AMap / Qwen Adapters
```

- React 页面不直接写 SQL，也不使用 service role 客户端。
- Agent 只能调用注册过的工具，不能任意访问数据库。
- 结构化业务数据通过 Repository 查询，不能用 RAG 代替。
- Knowledge Service 隐藏 pgvector、分块和重排实现。
- 高德、千问和 Supabase 的错误在 Adapter 边界归一化。
- Zod 同时校验用户 API 输入、工具参数和外部响应。
- 工具返回固定包含：`ok`、`source`、`resultCount`，以及 `data` 或稳定 `error`。

### 性能目标

| --------------- | ------------------------------ |
| 首页 LCP        | P75 小于 2.5 秒                |
| 普通业务查询    | P95 小于 2 秒                  |
| AI 首个可见事件 | P95 小于 4 秒                  |
| 多工具任务      | P95 小于 15 秒，并持续显示进度 |
| 普通工具超时    | 默认 8 秒，可配置              |

以上是作品集目标，需要通过部署后的测量确认，不能仅凭本地构建宣称达标。

### 可靠性

- 所有外部请求必须支持超时和取消。
- 可重试错误与不可重试错误使用不同错误码。
- 单个非关键工具失败时保留其他已成功结果。
- 幂等接口重复调用不能产生重复知识分块。

### 安全

- Supabase 业务表和用户表启用 RLS。
- 管理操作通过服务端权限执行，并验证管理员身份。
- 所有密钥只存于服务端环境变量。
- 知识文档被视为资料，不能覆盖系统指令或工具权限。

### 可访问性与兼容性

- 支持键盘操作、可见焦点和语义化状态提示。
- 重要图标提供文本或 `aria-label`。
- 支持现代 Chrome、Edge 和移动端浏览器。

## 17. 术语速查

| 术语             | 本项目中的含义                                                   |
| ---------------- | ---------------------------------------------------------------- |
| API              | 两个系统之间约定好的调用接口，例如小智调用高德搜索周边店铺       |
| Adapter          | 把高德、千问或 Supabase 的具体格式转换为项目内部统一格式的代码层 |
| Repository       | 封装数据库读写，让页面和 Agent 不需要知道 SQL 细节               |
| Zod              | 在运行时检查输入和外部返回是否符合约定格式的 TypeScript 工具     |
| RLS              | Supabase/PostgreSQL 的行级权限，决定某个用户能读取或修改哪些行   |
| Function Calling | 模型输出工具名和结构化参数，由服务端真正执行工具                 |
| RAG              | 先检索可信资料，再让模型基于资料回答并展示引用                   |
| Embedding        | 把文字转换为数字向量，用于寻找语义相近的内容                     |
| Rerank           | 对初步召回的资料进行第二次相关性排序                             |
| 幂等             | 同一个请求重复执行，不产生重复或不可控副作用                     |
| 降级             | 某项外部能力失败后，保留仍可信的部分结果并明确说明限制           |
| P95              | 100 次请求中约 95 次应快于该时间，用于衡量大多数用户的体验       |
