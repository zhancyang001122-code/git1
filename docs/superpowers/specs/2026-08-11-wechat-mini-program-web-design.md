# 小智微信小程序式 Web 改造设计

**日期：** 2026-08-11
**状态：** 已选择视觉方向，待书面评审
**选择：** B「微信结构 × 小智品牌」

## 1. 决策

小智继续使用 Next.js Web 技术栈并部署到 Vercel，不改造成原生微信小程序。前端采用微信小程序常见的信息结构、导航、列表、底部弹层和反馈方式，以便面试时用手机或桌面浏览器演示。

视觉方向不是“全站改成微信绿”，而是：

- 小程序结构负责熟悉感和操作效率。
- 小智蓝紫色负责 AI 品牌识别。
- 绿色只负责成功状态。
- 真实、历史、模拟和 AI 生成内容继续明确标识。

## 2. 为什么不改成真正微信小程序

真实微信小程序需要原生小程序、Taro 或 uni-app 前端，并涉及微信开发者账号、运行时 API、审核和双端维护。该工作不会增强当前作品集最重要的 FDE 能力证明，反而会分散 Agent、RAG、数据和企业工程闭环的完成时间。

因此 V1.0 的目标是“小程序式 Web 演示”，不是“微信审核发布”。README、PRD 和面试讲解必须保持这个边界。

## 3. 视觉系统

### 3.1 色彩

- 页面背景：`#F5F5F5`。
- 内容表面：`#FFFFFF`。
- 主文字：`#111111`。
- 品牌主色：`#4169F5`；按压态 `#3155E8`。
- AI 辅助色：`#7557F6`。
- 成功状态：`#07C160`。
- 普通区域避免大面积渐变、发光和强阴影。

### 3.2 形状和密度

- 顶部导航 48px，底部导航 56px，均叠加对应 safe area。
- 搜索框和所有交互目标至少 44px。
- Cell/卡片主要圆角 12px，大模块和弹层 16px。
- 使用 1px 浅灰分割线表达原生列表层级。
- 页面区块间距从 20px 收敛到 16px，提高信息效率。

## 4. 全局 App Shell

### 4.1 顶部导航

新增唯一 `MiniProgramNavigationBar`：

- 标题严格居中。
- 二级页具有真实返回行为。
- 右侧功能胶囊包含“更多”和“返回首页”。
- 首页不渲染无效返回入口。
- 移动端不渲染假的系统时间、电量或网络状态。

### 4.2 底部导航

保留首页、推荐、小智、消息、我的五栏，改为扁平等分：

- 删除中央 64px 上浮按钮和光晕。
- 当前栏目使用蓝色图标和文字。
- 小智通过首页 AI 主卡、选中态和对话 Composer 保持核心地位。
- 结构继续复用唯一 `BottomNavigation`。

## 5. 组件设计

### 5.1 新增组件

- `MiniProgramNavigationBar`
- `MiniProgramCapsule`
- `CellGroup` / `Cell`
- `ActionSheet`
- `Toast`
- `ConfirmDialog`
- `KnowledgeCitationCard`

这些组件只负责一种职责，业务页面通过明确 Props 使用，不复制交互实现。

### 5.2 现有组件调整

- `BottomNavigation`：删除上浮中央结构，统一 56px 扁平布局。
- `Button`：缩小视觉体积，但保留 44px 触控区和焦点状态。
- `DemoNotice`：改成小程序式浅色状态条。
- 业务卡片：减少阴影和大圆角，增加来源标签的层级一致性。
- `ChatExperience`：区分用户气泡、小智回答、工具步骤、业务卡片和知识引用。

## 6. 页面改造

### 首页

使用小程序导航、地点信息、44px 搜索、AI 主卡、四宫格服务入口、紧凑精选列表和扁平 TabBar。删除“后续将……”等未完成文案。

### 推荐

保留内容流，但筛选改为吸顶标签或 ActionSheet；卡片阴影减弱；“问小智”成为明确次级按钮。

### 小智与对话

欢迎页使用任务宫格和固定 Composer。对话页采用微信式左右消息布局，但结构化结果、工具进度和知识引用独立成卡，避免把复杂信息压进气泡。

### 消息与我的

改为标准 CellGroup。未读数、状态、副标题和箭头固定对齐；设置与危险操作分组。

### 房源、团购、超市、周边

筛选和排序使用 ActionSheet；列表卡片压缩装饰、突出事实和来源。定位必须主动触发，拒绝后可选择武林广场演示位置。

### 知识运营

保留移动演示能力，但明确生产环境应使用独立桌面后台和 RBAC。审核、驳回、发布和索引使用确认弹窗及状态反馈。

## 7. 数据流和架构

视觉改造不改变现有端到端架构：

```text
UI
  -> Application Services
      -> Business / Maps / Knowledge / User Ports
          -> Supabase / AMap / Qwen Adapters
```

ActionSheet、Toast 和导航只管理界面状态。业务查询、地图、RAG、用户偏好和工具审计继续经过现有服务边界，不把 SQL 或外部 API 调用移入 React 页面。

## 8. 错误、权限和降级

- 定位权限只在用户点击后请求；拒绝后提供演示位置。
- 高德失败保留已成功的房源或业务结果，并局部重试。
- 收藏、购物车和保存偏好使用 Toast；失败 Toast 必须有重试或明确入口。
- 删除、清空、覆盖和发布使用确认弹窗。
- RAG 低置信和冲突使用独立警示卡，不能显示为普通成功回答。
- Demo/Live、历史房源、高德和模拟业务标识不因视觉改造而弱化。

## 9. 测试与验收

### 组件测试

- 顶部返回、更多和返回首页按钮具有真实行为。
- ActionSheet 支持遮罩、Esc、焦点回收和键盘操作。
- Toast 通过 `aria-live` 播报并按时消失。
- ConfirmDialog 的取消和确认路径均有测试。
- BottomNavigation 五栏等分，小智不再上浮。

### 页面测试

- 360px、390px 和 430px 无横向滚动。
- 五个主页面共享相同 App Shell。
- 房源、地图、演示数据和知识引用来源仍正确显示。
- 定位拒绝和外部服务失败具有可恢复路径。
- 对话中的文本、工具进度、结构化卡片和引用保持可区分。

### 完整门槛

```bash
cd web
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
```

完成后重新生成所有主页面与关键业务页面的 430px 预览，由用户做视觉验收。

## 10. 实施顺序

1. 更新 Token、页面背景和最大画布。
2. 实现顶部导航、功能胶囊和扁平 BottomNavigation。
3. 实现 Cell、ActionSheet、Toast 和 ConfirmDialog。
4. 改造首页和小智，建立页面范式。
5. 改造推荐、消息、我的和业务页面。
6. 补组件测试、页面测试、E2E 和预览。
7. 恢复并完成 RAG 功能接入，确保知识引用使用新组件。

## 11. 非目标

- 不引入 Taro、uni-app 或微信原生运行时。
- 不接入微信登录、支付、订阅消息或分享 SDK。
- 不复制微信商标、系统状态栏或不可用的装饰控件。
- 不因视觉改造改变 Supabase、Agent、Maps 和 Knowledge 的领域边界。
