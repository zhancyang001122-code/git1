# RAG Embedding 恢复与防复发报告

日期：2026-08-13

## 结论

Production 的作品集首方知识链路已经恢复并重新通过固定评测 20/20，其中 4/4 自然问法生成用例通过。四份材料的当前发布状态均为可检索且评测通过，重复执行导入不会重复发布。

这不是一次单点代码错误。排查过程中依次发现了上游 Embedding 瞬时失败、业务日期时区错误、Agent 取证范围不完整、导入任务不可恢复，以及历史任务结果覆盖当前发布状态五个问题。每个问题都留下了自动测试或幂等恢复机制。

## 影响

- 新版“账号、登录与长期记忆边界”材料首次索引失败，导致该版本暂时不可搜索。
- 索引恢复后，上海时间已经生效的材料仍可能被 UTC 日期过滤，四条账号相关评测无法召回。
- 检索恢复后，登录边界问题可能不调用知识工具，或者混入产品能力文章，生成评测无法稳定通过。
- 旧导入脚本看到相同版本就跳过，不能恢复失败任务；恢复后又可能把历史失败快照误报为当前状态。

## 原因与证据边界

1. **Embedding 上游瞬时失败**：初次失败时日志没有保留安全的上游状态码，因此不能诚实断言是某一个精确供应商错误。加入仅记录状态码、错误码、错误类型和请求 ID 的安全诊断后，同一个任务一次重试成功；已知额度也充足，所以可以排除持续性的无权限或额度耗尽，最合理结论是瞬时上游或网络故障，精确上游原因仍未知。
2. **业务日期使用 UTC**：应用层 `toISOString()` 与 SQL `current_date` 都按 UTC 判断有效期。在 `Asia/Shanghai` 已进入 8 月 13 日而 UTC 仍是 8 月 12 日时，新材料被两层过滤。
3. **取证规则缺少账号边界**：Grounding Policy 没有覆盖登录、认证和验收类问题；Query Planner 也没有把这些问题限定到账号材料。
4. **任务恢复条件错误**：导入脚本仅凭“已存在 published 版本”就跳过，没有检查持久化索引任务和当前发布结果。
5. **历史与当前状态混淆**：索引任务的 `result_json` 是历史快照；候选的 `publication_result_json` 才是重新评测后的当前发布状态。

## 修复

- `df0fa9e`：为 Embedding 失败增加密钥安全的白名单诊断信息。
- `a8b9a6d`：应用与 Supabase 混合检索统一使用 `Asia/Shanghai` 业务日期。
- `887ee2a`：登录、认证、验收问题必须先从知识库取证。
- `fe8c6f6`：账号边界问题限定检索到 `portfolio_data_memory`，并允许不改变事实含义的表达变体。
- `cded719`：导入器按持久化任务状态恢复失败或等待中的任务；发布后重新评测可更新当前状态。
- `e03d036`：导入摘要读取候选当前发布状态，不再使用历史任务快照代替当前结论。

## 验证

- 同一个失败索引任务在一次重试后成功，账号材料生成 2 个可检索切片。
- 四个账号相关问题均召回正确材料，且不再混入产品能力文章。
- Production 固定集：20/20 PASS；自然问法生成：4/4 PASS；结果写入 `ai_eval_runs`。
- 四份首方材料再次执行导入均返回 `already_published` 与 `passed`，没有重复写入或重复索引。
- 本轮代码质量门通过：127 个测试文件、537 项测试、43 个生产路由，以及 28 个迁移、33 张启用 RLS 的表。

## 防复发

- 日志只保留可用于排障的白名单元数据，不输出输入正文、响应正文、请求头或密钥。
- 跨午夜自动测试固定验证上海业务日期，迁移检查固定验证 SQL 时区。
- 评测集包含账号认证自然问法，并同时检查工具调用、事实、版本、来源和引用范围。
- 导入任务以持久化状态机恢复，尊重 `available_at` 和重试退避；只有“当前版本、索引成功、当前发布结果可检索且通过”才允许跳过。
- 当前状态与历史审计分开保存：历史记录不删除，当前结论也不会被旧失败快照覆盖。

## 仍未完成的外部项

- 仓库仍没有经授权的企业客服资料，不能把作品集首方评测描述为企业客户知识库交付。
- `qwen3-rerank` 已有 Adapter 和契约测试，但 Vercel Production 尚未配置百炼 Workspace 专属地址，因此没有在线调用证据。
