# 本机历史房源 HTTP 接入报告

日期：2026-08-11

## 结论

小智已可在本机混合演示模式下，通过服务器端 Adapter 查询用户现有的 2024-11 杭州租房 SQLite 快照。该能力不依赖高德、千问或 Supabase 账号，并持续明确标记为历史数据。

当前不是公网生产就绪：房源服务只在本机启动，Vercel 无法访问用户电脑；真实数据的公开再分发许可也尚未确认。

## 实现边界

- 新增独立 `services/housing-api`，不修改原 WorkBuddy 技能目录。
- FastAPI 接口为 `POST /v1/houses/search` 与 `GET /health`。
- SQLite 使用 `mode=ro` 和 `PRAGMA query_only=ON`，查询前后测试库哈希一致。
- 请求使用 Bearer API Key、16KB 请求体限制、固定窗口限流、requestId 和安全错误结构。
- 只返回白名单字段；不返回内部自增 ID、`raw`、联系方式、数据库路径或异常堆栈。
- Next.js 通过 server-only `HousingHttpAdapter` 调用并使用 Zod 校验外部响应。
- 只在查询中心匹配已配置的武林广场 WGS84 坐标时调用真实服务；其他地点在接入高德地理编码和坐标转换前明确拒绝。
- 数据没有可靠宠物政策字段，因此真实房源模式拒绝宠物筛选，不把缺失值映射为“不允许”。
- HTTP 房源卡不跳转到尚不存在的内部详情页，只提供受校验的历史来源链接。

## 发现并修正的问题

1. 原型 `GET /nearby` 会调用可写建表初始化逻辑，并返回整行数据库记录，不能直接作为正式边界。
2. 原型响应可能包含 `raw` 和内部 ID；正式服务改为 SQL 与响应双重字段白名单。
3. 旧 Demo 文案在地图工具完成后会把真实历史房源误称为“演示房源”；已改为“历史库或演示数据”，并声明不代表当前可租或当前价格。
4. 真实库部分记录缺少区县和地址；接口返回“信息缺失”，不补造位置文本。

## 验证证据

- Python：Ruff 通过；Mypy strict 通过；Pytest 7/7。
- Web：ESLint 通过；TypeScript strict 通过；Vitest 88 个文件、306 项测试通过；Next.js 生产构建 37 个路由通过。
- 真实数据库：武林广场 2km、整租、5000 元以内返回 3 条历史记录；抽样查询约 97ms。
- 端到端：普通 Demo 回归 46 项通过、1 项因未配置房源服务按设计跳过；`小智 → Tool Executor → HousingHttpAdapter → FastAPI → 真实 SQLite` 专项测试在真实服务启动后 1/1 通过。
- 服务测试进程结束后已确认 8000 端口无监听。

## 下一阶段依赖

- 高德 Web Service Key：地名解析、GCJ-02/WGS84 坐标处理、真实 POI 与步行路线。
- 千问与 Supabase：真实 Agent 推理、对话持久化、RLS 和云端业务数据。
- 正式知识材料：见后续知识材料清单；当前不得把演示知识库描述为用户资料。
- 数据许可：若公开展示真实明细，需确认购买数据是否允许网页再分发；否则公开版只展示脱敏样例或聚合结果。
