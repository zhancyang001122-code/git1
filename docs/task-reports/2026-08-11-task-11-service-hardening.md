# Task 11 — 安全、可观测性、韧性与性能加固

## 完成范围

- 新增统一日志脱敏：敏感字段、手机号和精确地址递归过滤；日志仅保留 requestId、耗时、错误码、结果数等诊断字段。
- API 接受通过 UUID 校验的上游 requestId，否则生成新 UUID；Chat、地图、健康检查、反馈和知识运营接口均返回 `x-request-id`。
- Chat、Feedback、知识发布和索引加入客户端键哈希后的固定窗口限流，429 响应包含稳定错误和 `retry-after`。
- JSON 请求在进入 Zod 和外部服务前执行 UTF-8 字节上限检查，避免只限制字段字符数而允许超大请求体。
- 高德 GET、Embedding 和 Rerank 对可重试故障最多重试一次；鉴权、参数、用户取消等错误不重试。千问生成因非幂等而不自动重试，只执行超时、错误归一化和熔断。
- 外部适配器使用进程级共享熔断器，连续三次可重试失败后短路 30 秒；返回稳定、可降级的错误。
- RAG 工具结果增加 `evidence_only` 边界；检索资料中的指令文本不能升级为系统消息或工具权限。
- 新增进程内聚合耗时指标与聊天结构化完成日志，不记录完整 Prompt 或隐私正文。
- Playwright 增加首页性能预算：导航小于 10 秒、脚本传输小于 2 MB、脚本数量少于 40。

## 真实边界

- 当前限流、熔断和指标都是单 Node.js 进程状态，足够用于本地作品集和单实例演示，但不是多实例生产方案。
- Vercel 生产部署需要把限流迁移到共享 Redis/Upstash，把指标和 JSON 日志接入集中可观测平台。
- 当前外部服务仍未配置，因此测试使用确定性替身验证重试、熔断、超时和错误归一化，没有宣称完成真实供应商压测。
