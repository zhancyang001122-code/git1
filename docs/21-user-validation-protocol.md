# 租房决策助手真实用户验证方案

## 目的

自动化测试只能证明系统按契约工作，不能证明用户真的更快、更容易做决定。本方案用 3–5 位近期有租房经历的目标用户，验证主演示是否清楚、有用、可信。

## 参与者

- 近两年在杭州或绍兴租过房，或未来半年准备租房；
- 不要求懂 AI 或编程；
- 不使用真实身份证号、合同、手机号或未公开房源信息。

## 测试任务

让参与者独立打开 Production，不先讲解功能，并完成：

> 预算 3500 元，在武林广场附近找一居室参考；确认附近是否有地铁和超市；说出签约前至少三项要核验的信息，并找到规则原文。

观察者只记录，不代替点击。卡住 60 秒后才能给一次中性提示。

## 记录字段

| 字段         | 记录方式                                     |
| ------------ | -------------------------------------------- |
| 是否完成     | 四项子任务全部完成才算是                     |
| 总用时       | 从打开首页到找到官方原文                     |
| 追问次数     | 用户为获得完整结果又输入了几次               |
| 来源理解     | 能否说清历史房源、高德和官方资料的区别       |
| 误解         | 是否把历史房源当成当前可租或把摘要当法律意见 |
| 最有价值部分 | 用户原话，需征得记录许可                     |
| 卡点         | 页面、文案、速度、结果或信任问题             |

## 通过门槛

- 至少 3 人完成；
- 至少 80% 的子任务完成；
- 参与者均能识别房源是历史数据；
- 参与者均能找到至少一条官方原文；
- 不出现“系统保证可租”或“系统提供法律结论”的错误理解。

样本少于 5 人时，只写“探索性可用性测试”，不能把结果外推为市场结论。

## 访谈问题

1. 你刚才最想先看到什么？
2. 哪个结果让你最不信任？为什么？
3. 历史房源对你的用途是什么？
4. 官方规则引用是否比普通聊天回答更有帮助？
5. 如果只能保留一个功能，你会保留什么？

## 结果填写规则

测试前不要在 README 或案例页填写任何效率提升数字。完成后保留匿名原始记录，新增一份日期化任务报告，写明参与人数、任务、原始观察、失败案例和改动；平均值、中位数和完成率必须可以由原始记录复算。
