# 小智租房决策助手：交付案例

## 一句话结论

小智把“按预算找历史房源、核验周边配套、理解签约规则”从三个分散入口收敛为一个可追溯的对话任务。它是面试作品集，不提供实时房态，不替代租赁平台，也不构成法律意见。

## 问题与判断

初到杭州的租房者常同时关心预算、户型、目标地点、生活配套和签约风险。普通筛选页需要来回切换；纯聊天回答又可能把历史房源、推测距离或模型记忆当成事实。

因此系统没有把所有内容塞进 RAG：

| 事实                         | 正确来源             | 原因                               |
| ---------------------------- | -------------------- | ---------------------------------- |
| 价格、户型、历史记录         | Supabase 结构化查询  | 必须满足精确条件                   |
| 地点、POI、路线              | 高德 Web Service API | 外部地图事实会变化                 |
| 签约、押金、备案依据         | 已发布的官方公开知识 | 需要版本、生效日期和引用           |
| 理解问题、选择工具、组织答案 | 千问                 | 模型负责推理与表达，不负责创造事实 |

## 主演示任务

> 我预算 3500 元，想找武林广场附近的一居室。请查询 2024 年历史房源，再找附近的地铁和超市，并说明签约前需要核验哪些信息、是否需要办理网签备案。

验收时必须看到：

1. `search_houses` 返回带 `2024-11` 边界的房源卡；
2. `search_nearby_places` 返回标记为高德来源的地点卡；
3. `search_knowledge` 返回 `public_official` 引用；
4. 引用包含标题、版本、生效日期、`chunkId` 和可打开的 HTTPS 官方原文；
5. 任一工具失败时，回答只保留其余可验证结果并说明缺口。

## 已有工程证据

- Supabase 中有 60,202 条 2024-11 历史房源记录，界面不将其描述为当前可租。
- Production 已接通 Supabase、千问、高德和历史房源服务。
- 原有首方 RAG 固定评测为 20/20，生成评测为 4/4。
- 官方资料集包含国家《住房租赁条例》和杭州租房风险提示；两份资料均已完成 Production 发布、真实 Embedding 与索引，10 条独立检索/拒答用例 10/10 通过。
- 数据库迁移、Zod Schema、工具契约、引用 UI、生产预检和 Playwright 回归共同约束主流程。

同轮主演示已在精确部署提交 `b0a1ae2` 上完成 Production 预检：回答同时返回历史房源卡、高德地点卡和带版本、生效日期、官方原文链接的租赁知识引用。完整命令与边界见 `docs/task-reports/2026-08-25-rental-decision-production.md`。

## 诚实边界

- 房源是历史筛选参考，不代表当前可租、真实报价或可直接签约。
- 官方资料是摘要，用户应打开原文并核对所在地最新办理指南。
- 团购、超市交易和社区内容是演示业务，不属于租房主线的真实交付。
- 目前没有真实用户效率样本，不能声称节省时间、提升转化或降低投诉。
- 目前没有企业内部客服资料，不能声称已交付企业知识库。

## 面试时的 30 秒表达

> 我把原来的泛本地生活 Demo 收敛成一条租房决策薄切片。精确房源查 Supabase，周边和路线查高德，签约规则走带版本和原文链接的 RAG，千问只负责理解、编排和表达。Production 预检不是检查页面有没有字，而是验证三个工具在同一任务中真实成功。当前工程链路有证据，但真实用户效率还没有样本，所以我不会编造 ROI。
